## Architecture and authorization

- Opt-in v2 catalogs declare private epistemic annotations, six base subjects, account-version cores, informational disclosure cores and finite rules. Rules allow at most two alternatives of sixteen committed inspection/testimony references, with owned local references and exact normalized request aliases.
- Current account pointers, first-committed semantic receipts and policy revision are private, case/session-local state. Receipts retain initial speaker/version/turn after history/cache eviction and remain bounded by the validated catalog.
- First gated disclosure requires an explicit eligible rule. Topics/revisits use current account authority; repeated transitions return the current version without duplicate receipts or backward movement. Private truth, mistaken belief, player assertions, pressure and model output cannot unlock a secret.
- All changes stage with existing dialogue/history/emotion/cache candidates. Final authorization, policy revision, generation, room, lifecycle and session guards recheck before installation, including after public/result projection. Discard/stale/projection failures install no candidate changes; authorized offline/provider fallback can commit successfully.
- Cache keys bind trusted case/version, policy revision/current accounts and existing exact pools. Exact whole-dialogue authorization is preserved across structured and legacy adapters. Private policy/receipts never enter provider context or public HTTP.
