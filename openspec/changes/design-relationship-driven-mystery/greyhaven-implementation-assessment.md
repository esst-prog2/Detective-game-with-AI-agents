## Observed reuse and constraints

The engine already takes case/catalog inputs, holds inspected and committed-discussed IDs, supports static rooms, evidence prompts, comparisons, six choices and text, and validates exact current performance pairs before atomic installation. Session/API guards, escaped browser output and private finality remain valuable. Existing collection tests with larger synthetic casts do not prove Greyhaven integration. `validateCase` still encodes the original size assumptions; default catalog resolution and `explainAshcroft` are case-specific. Current `coreAllowed` only has single evidence eligibility. Clarification repeats lastCore with framing, not a new informational facet. Existing family/social dossier edges have no disclosure semantics. HTTP create body is currently exactly `{}`; there is no case selector.

Keep original case data, original reviewed testimony, Alice's uncertain recognition/debt annotation, demeanor precedence and existing failure fallbacks unchanged. No model receives this story bible. Full `node --test`, Chromium, build and privacy results from the previous milestone are historical, not results of this assessment.

## Integration and specification decisions still required

Recommend a stable explicit case ID with Ashcroft default when omitted, rather than identifying by mutable display title. A future implementation proposal must specify exact HTTP creation schema, CLI selection and browser entry behavior; current strict `{}` tests must remain valid. These are implementation requirements awaiting specification approval, not permission to alter those contracts now.

Keep six substantive base subjects for each Greyhaven NPC in the first version, matching existing validators instead of adding sparse-topic flexibility. Cases can supply their own reviewed question labels/aliases; original Ashcroft labels/behavior stay unchanged. Location C intentionally has no resident; R has two. Verify those patterns through actual adapters before claiming compatibility. Static present interview positions avoid schedules, waiting mechanics or repeating the murder simulation.

Existing fixed-knowledge/dialogue-naturalness wording must receive explicit future **case-scoped** deltas: conditional accounts and informative facets are authored semantic changes, not free paraphrase. Existing stateful emotion, naturalness, hybrid interface and mystery-deduction contracts need compatibility review. Safe performance exact-pair/minimal-prompt/privacy requirements remain intact. No canonical specs are edited in this planning change; `skip_specs: true` remains appropriate.

## Content cost and scope correction

Earlier ~42 speech bodies/eight clarifications were concept-stage estimates, not approved caps. Detailed design now proposes 30 base bodies,20 targeted facets (I-F included there),3 progression bodies M1/M2/O1, evidence bodies including R-F/I-P; J-C is now an ordinary directly available call account, and two comparison responses (C-V reuses M1). Some base bodies can serve J-B/J-P/R-H/M-S; do not count reuse as new text. Budget roughly **60-70 distinct reviewed bodies plus short guidance**, to be measured with the eventual literal inventory. Do not claim the old 42 estimate still covers this story. A content audit may reduce redundant facets without dropping source limitations or alternative routes. No delivery variants are required initially; one exact reviewed fallback per body works offline. The focused revision adds four useful skeptical facets (20 total) and expands existing statements, not a new disclosure arc. The former 55-65 estimate is superseded by 60-70 pending a literal inventory.

Five interviewees/five rooms/eight clue inspections and two account arcs remain the minimum. Multiple stages in the mother arc are not multiple independent secret plots. Deferring Owen's final admission would reduce emotional payoff; recommend retaining it, but not making it essential for murder. Optional later work: richer reactions between relatives, more delivery variants, art/voice, moving NPCs, persistence, additional cases, numerical trust or broader social simulation. No new model agent, database, framework or generated facts are needed.

## Focused revision consequences

The fixed house telephone and sightline map are authored setting facts in existing G1/G3/G5 inspections, not a new call simulation or wiring mechanic. J-C needs no evidence gate; public labels can cue it from J-B/G3 while direct text remains available immediately. M-S cover identification and R-F collection/storage distinction fit existing bounded testimony. O0 reports receiver pickup, not caller identity. Source/permission tests must reject upgrading recognition to visual proof or reporting private 20:38 from any of these. The revised finite support sets retain four inspections/eight accounts each.

The earlier checker existed only as transient Node stdin commands. [check-greyhaven-design.mjs](check-greyhaven-design.mjs) now preserves and extends that documentation-only checker inside this planning directory so review can reproduce it; it imports no game code and changes no runtime test file.
