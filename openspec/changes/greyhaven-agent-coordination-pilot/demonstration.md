# Teacher demonstration · One interview changes the next

**Question to watch for.** After hearing Owen, does Mara pick up the Game Master's approach while still speaking and acting for herself? Run each comparison in a fresh Greyhaven preview session. Use the same public actions and the independent [preview oracle](../../../test-support/greyhaven-preview-oracle.js). This is a proposed script for E1 acceptance.

| Step | Player action | Observable result |
| --- | --- | --- |
| 1 | In reception ask Mara “Where were you?” Travel to the boathouse. | Receive Mara's original account. Direction is still empty. |
| 2 | Ask Owen “Explain the maintenance fund payment and the argument.” | Guidance. The payment explanation stays locked and the role-call count is zero. |
| 3 | Ask Owen “Where were you?” and “What do you mean by work?” Inspect the pump worksheet. Try the payment question again. | Receive the original account and work clarification. With only one record the payment question still yields guidance. |
| 4 | Inspect the repayment demand. Choose “Ask Owen to explain the maintenance-fund payment and the argument.” | The engine now authorizes the account revision. The director sees recent committed activity and proposes a two-witness strategy. Owen chooses one of his two permitted moves. His complete authorized account accompanies the move. |
| 5 | Travel to reception and ask Mara “Are you saying you watched him the whole time?” | The validated direction survives travel. Mara independently chooses her response to a source question within that approach. She gives her own guarded account and gains no knowledge of Owen's payment. |
| 6 | Repeat Mara's source question. | The handoff has been consumed. Ordinary preview delivery resumes. The preview remains active. |

**Compare three modes.** Show the credential-free baseline first. Then replay with deterministic provider fixtures and vary only the director's answer. For each strategy, replay once with both actors choosing their first permitted move and once with both choosing their second. Finally run the same script live with the actual client. In the local trace display role, validated instruction, accepted reaction, mode, call ordinal, elapsed time and metered usage. Only show labels after the audience has read the replies. Label offline, scripted, live and fallback explicitly. Use live status only for a validated provider response. If the network fails, show the fallback as observed and retain the live acceptance item as outstanding.

**Test whether player history matters.** Run two further matched histories against a history-sensitive director fixture. Before step 4, in one session repeat a baseless challenge after Owen's account. In the other, ask his authorized work clarification instead. Keep identical inspections and the same eligible payment core. Verify the actual request contains different committed tags, both strategies remain available in both sessions, and the returned strategy determines the two speakers' offered moves. Failed/unsupported questions never add pressure tags. For the live demonstration record the actual strategy and compare it with the visible history. One live run establishes provenance, not a statistical claim about model preferences.
